Bridges are replaced by anti-corruption layers (ACLs), and Outcome Events are named a saga. `src/bridges/` and the `#bridges/*` import alias are gone. A context that reads another holds the read in its own `adapters/outbound/<context>-<upstream>-acl.ts`, which imports only the upstream's `index.ts`, calls its `*Get` or `*List` Use cases with its own machine Actor and returns the downstream's own shape. Its slot in the ports is `<context><Upstream>Acl` in `application/ports.ts` (was `<context><Upstream>Reader`); the `<Context>Readers` type, the reader memory fakes and their exports are gone. `<context>ContextCreate({ connections, upstream })`, `<context>PortsCreate(connections, upstream)` and `<context>PortsMemoryCreate(upstream)` take the upstream contexts themselves (`upstream: { customer: customerContext }` in `src/use-cases.ts`), typed `<Context>Upstream` in `adapters/outbound/index.ts`. The Template's `index.ts` exports `<Context>Context`, the type its `<context>ContextCreate` returns, so a new context can be an upstream. Tests build the real upstream on memory adapters with the test helper `<context>TestUpstreamCreate()` in `adapters/outbound/<context>-test-upstream.ts`, pass it to every `<context>PortsMemoryCreate(upstream)` call, and create the rows they need through the upstream's Use cases. `pnpm context-create <context> --reads <upstream>` writes all of this. Architecture rule A11 now checks ACLs: one upstream, through its `index.ts`, `*Get` and `*List` Use cases only. A6 lets an ACL import its upstream's `index.ts`, and a seed import the types of a context its context has an ACL for, so a downstream seed can list upstream rows through `upstream`, which it gets in `index.ts`. Inside a context only tests and test helpers may import `src/use-cases.ts` or `src/connections.ts`. `docs/agents/bridges.md` is now `docs/agents/acl.md`, with a Saga section in place of Outcome Events.

To upgrade a Project: for each Bridge `src/bridges/<context>-<upstream>-reader.ts`, move it to `src/contexts/<context>/adapters/outbound/<context>-<upstream>-acl.ts` and rename it `<context><Upstream>AclCreate`, taking `Pick<<Upstream>Context, "useCases">` (add `export type <Upstream>Context = ReturnType<typeof <upstream>ContextCreate>;` to the upstream's `index.ts`). Rename the reader port to `<context><Upstream>Acl`, delete `<Context>Readers` and the reader's memory fake, and follow `app@<this version>`'s `pnpm context-create <context> --reads <upstream>` output for the rest: `<Context>Upstream` and the ACL in `<context>PortsCreate` and `<context>PortsMemoryCreate`, `upstream: { <upstream>: <upstream>Context }` in `contextsCreate`, and `<context>TestUpstreamCreate` passed to every `<context>PortsMemoryCreate` call in its tests; tests that used the fake now create upstream rows through the upstream's Use cases. Drop `#bridges/*` from `package.json` `imports` and delete `src/bridges/`. `pnpm check` and `pnpm test` name what is left: A6 for a context file that still imports another context, A11 for an ACL that writes.
