A bounded context can hold several Aggregates. `pnpm domain-create` is replaced by two commands: `pnpm context-create <context> [--reads <context>]` writes a context's shell (its entry, ports, transaction, Use cases, adapters' entries, a `CONTEXT.md` stub and its wiring), and `pnpm aggregate-create <context> <aggregate>` adds an Aggregate to it with the part flags `--bare`, `--analytics`, `--cache`, `--live`, `--pages`, `--schedule` and `--seed`. `docs/agents/domain-create.md` is now `docs/agents/context-create.md`. The marker comments are renamed: `// domain-create: <slot>` is `// wiring: <slot>` (`# wiring:` in `.env.schema`) and `domains-start`/`domains-end` are `wiring: contexts-start`/`wiring: contexts-end`. The Template's `foo` context gains a second Aggregate, Bar, a note on one Foo that is deleted with it. Architecture rules: A23 lets a context's export start with one of its Aggregates' names, A14 asks for a deleted handler only for an id from another context (its context or one of its Aggregates), A16 lets a span attribute name the Aggregate, and the new A28 fails a transaction whose work reaches two Aggregates' repositories without a `// invariant: <what>` comment right above it. An Aggregate is a `domain/<name>.ts` model with its own `adapters/outbound/<name>-table.ts`; `structure.test.ts` allows a `CONTEXT.md` and each Aggregate's `<name>-error-status.ts` at a context root. Only a context's first table exports its `pgSchema`, since drizzle-kit refuses two exported schemas of one name.

To upgrade a Project: after `pnpm template-upgrade`, replace `domain-create:` with `wiring:` and `domains-start`/`domains-end` with `wiring: contexts-start`/`wiring: contexts-end` in every file outside `src/contexts/`, and where you ran `pnpm domain-create <name>`, now run `pnpm context-create <name>` and then `pnpm aggregate-create <name> <name>`. For `aggregate-create` to add a second Aggregate to a context made by `domain-create`, give that context's shared files the `// wiring: <slot>` markers `app@<this version>:apps/app/src/contexts/foo/` has (`repositories`, `errors`, `ports`, `transaction-ports`, `use-cases`, `exports`, `read-repositories` and the memory state's), and move the memory state from `<name>-repository.memory.ts` into `<name>-transaction.memory.ts` as foo has it. Then run `pnpm check`: A28 reports any Use case that already writes two Aggregates in one transaction, which needs its `// invariant:` comment.
