A bounded context can hold several Aggregates. `pnpm domain-create` is replaced by two commands: `pnpm context-create <context> [--reads <context>]` writes a context's shell (its entry, ports, transaction, Use cases, adapters' entries, a `CONTEXT.md` stub and its wiring), and `pnpm aggregate-create <context> <aggregate>` adds an Aggregate to it with the part flags `--bare`, `--analytics`, `--cache`, `--live`, `--pages`, `--schedule` and `--seed`. `docs/agents/domain-create.md` is now `docs/agents/context-create.md`. The marker comments are renamed: `// domain-create: <slot>` is `// wiring: <slot>` (`# wiring:` in `.env.schema`) and `domains-start`/`domains-end` are `wiring: contexts-start`/`wiring: contexts-end`. The Template's `foo` context gains a second Aggregate, Bar, a note on one Foo that is deleted with it. Architecture rules: A23 lets a context's export start with one of its Aggregates' names, A14 asks for a deleted handler only for an id from another context (its context or one of its Aggregates), and the new A28 fails a Use case that writes two Aggregates' repositories without a `// invariant: <what>` comment.

To upgrade a Project: after `pnpm template-upgrade`, replace `domain-create:` with `wiring:` and `domains-start`/`domains-end` with `wiring: contexts-start`/`wiring: contexts-end` in every file outside `src/contexts/`, and use `pnpm context-create` and `pnpm aggregate-create` where you used `pnpm domain-create` (`pnpm aggregate-create <name> <name>` adds an Aggregate to an existing context). For `aggregate-create` to add a second Aggregate to a context made by `domain-create`, give that context's shared files the `// wiring: <slot>` markers `app@<this version>:apps/app/src/contexts/foo/` has (`repositories`, `errors`, `ports`, `transaction-ports`, `use-cases`, `exports`, `read-repositories` and the memory state's), and move the memory state from `<name>-repository.memory.ts` into `<name>-transaction.memory.ts` as foo has it. Then run `pnpm check`: A28 reports any Use case that already writes two Aggregates in one transaction, which needs its `// invariant:` comment.
