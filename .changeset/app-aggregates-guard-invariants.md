Aggregates guard their own invariants. Each Aggregate's `domain/<aggregate>.ts` now holds its schemas, its transitions (pure functions that make or change it and return `Result`) and its specifications (predicates ending `Is`, `Has` or `Can`); the one-file Rules are gone. In the Template, `foo-update-can.ts`, `foo-delete-can.ts` and `foo-stale-is.ts` fold into `domain/foo.ts` as `fooUpdateCan`, `fooDeleteCan` and `fooStaleBefore` (the unused `fooStaleIs` is dropped), beside the new `fooNew` and `fooRename(foo, { actor, name, now })`, which returns `FooForbiddenError` itself; Bar gets `barNew`. A Use case loads, calls a transition, saves what it returns and publishes. `aggregate-create` writes this shape. Architecture rules: the new A29 fails a non-test `application/` file that types a literal as an Aggregate root, casts to one, spreads or assigns to a variable named for one or loaded by a repository `find…`, or hands a literal to its repository's `insert`/`update`; A2 lets `domain/` import the result package's values (`ok`, `err`); A3 and A4 fail an adapter that imports a function from its context's `domain/` (a transition or specification), directly, through `index.ts` or by a namespace import; A27's message for `domain/` now says a transition returns `err(...)`. `structure.test.ts` term-checks each Aggregate's `domain/` file even with a test beside it. A set-based repository write (a Schedule's single `UPDATE ... WHERE`, an Event handler's cleanup) stays the one change that skips the transitions (`docs/agents/schedules.md`).

To upgrade a Project: after `pnpm template-upgrade`, for each Aggregate move its Rule files (`domain/<aggregate>-*.ts`) into `domain/<aggregate>.ts` and fix the imports. Then run `pnpm check` and `pnpm test`: for each A29 hit, write a transition in `domain/<aggregate>.ts` (`<aggregate>New` for a new one, a verb such as `<aggregate>Rename` for a change, taking the Actor and the time as inputs and returning `err(...)` for a forbidden or invalid change) and have the Use case call it and save its value; for each A3 or A4 hit, move the logic into a Use case, or repeat a predicate in the memory adapter and hold it equal to Postgres in the repository contract test. Fold each Rule test into a Use case test where one already covers it, and keep the rest as tests of `domain/<aggregate>.ts`. `app@<this version>:apps/app/src/contexts/foo/domain/` shows the shape.
