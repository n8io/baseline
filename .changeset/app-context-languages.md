Each bounded context has its own language, and `CONTEXT-MAP.md` is a real context map. `CONTEXT.md` now holds only the shared `## Architecture` terms; each context's terms live in `src/contexts/<context>/CONTEXT.md`, which says its subdomain type (`Subdomain: core`, `supporting` or `generic`) above its `## Language`. A Project's new `CONTEXT-MAP.md` lists each context with its subdomain type and its language in a `## Contexts` table, and how contexts relate (downstream, upstream, through an `ACL`, `Domain events` or both) in a `## Relationships` table; `docs/agents/context-create.md` gives the format, and `scripts/glossary-check.test.ts` checks the map against `src/contexts/`. `pnpm context-create <context>` refuses a context the map does not list and writes its `CONTEXT.md` with the map's subdomain type; `pnpm aggregate-create` looks for the Aggregate's `**Term**:` in that context's `CONTEXT.md`. `pnpm glossary-check` now reads the map by default: a file in a context is held to its own language and the shared one, so another context's term is a hit except in the `adapters/` of a context the map lists downstream of it, and an alias written capitalized (`Rule`) matches only that case, so "architecture rule" or "read model" no longer warn. `answersWrite` no longer takes `terms`.

To upgrade a Project: `pnpm template-upgrade` brings `CONTEXT-MAP.md` and keeps your terms under `CONTEXT.md`'s `## Language`. Then, for each context, add its row to `CONTEXT-MAP.md`, create `src/contexts/<context>/CONTEXT.md` (a title, `Subdomain: <type>`, a line on what it does, then `## Language`), move its terms there from `CONTEXT.md`, and add a `## Relationships` row for each context it reads through a Bridge or whose Events it handles. Delete `CONTEXT.md`'s `## Language` heading once it is empty. `pnpm test` names what is still missing.
