# Use plain, model-first terms

Status: accepted, 2026-11-21

ADR 0001 took the DDD and hexagonal vocabulary whole, and Nate found it academic: most TypeScript developers say model, entry point and public API, not Aggregate, composition root and Published language. We replaced the terms with the plain ones. Aggregate, Aggregate root and Entity become one term, **Model**: the business object a context saves and loads through one Repository, a Zod schema with its value objects and model functions; the rule is now "one Model per transaction" (A28 and its `// invariant:` escape behave as before). Transition becomes **Model function**, and a predicate is a model function that answers yes or no, named model first, then `Is`, `Has` or `Can`, so it reads as English (`invoiceIsPaid`, `invoiceCanRefund`, not `invoicePaidIs`); this replaces the predicate-suffix part of ADR 0002. Composition root becomes **Entry point**, Published language becomes **Public contract**, and a Part becomes an **Option**. Specification is no longer a term, and Seam, Module, Interface, Intake and Subdomain leave the glossary because nobody used them to decide anything. `aggregate-create` is now `model-create`. We kept Value object, Use case, Port, Adapter and Repository because they are already the words developers use.
